Found by this run, and fixed (Classic Monks feat/monks-central, Pro and Free; see phase-4a3)
  Classic Monks get-comments (Pro functions/ai/abilities/get-comments.php:91 at cc4e689f, and Free
  functions/monks-central/abilities/get-comments.php:81) declares the output field author_email
  as {"type": "string", "format": "email"}. WordPress validates ability output, and an empty
  string is not a valid email, so one comment without an email (WP-CLI or imported comments,
  pingbacks and trackbacks, sites that don't require an email) makes the whole list fail.
  Reproduced on mc-a (comment 5) and monks-central-test (comment 4): the "approved" list fails on
  both, and the "pending" list on mc-a failed while comment 5 was pending, then read again once it
  was approved. Moderating by id is not affected. The final review hit the same error (its
  "jq: parse error" line under phase-4a) without noticing it. Likely fix, in the plugin: drop
  "format": "email" from author_email (or allow an empty string) in both editions, with a test that
  lists a comment with no email. Done: author_email is a plain string, and both suites' wrapper
  tests list a comment with no email.
