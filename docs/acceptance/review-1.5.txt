Monks Central, review 1.5: Phase 1 live acceptance re-run on WordPress Studio sites
Run: 2026-10-28, Linux (Hyprland), main after df780a7. Driver: crates/core/examples/acceptance.rs (same core
API as the app). The browser step is played by the driver: a login cookie made with `studio wp` for the
site's admin, then the site's real consent page, submitted with every tool group, Full access and
"This is my Monks Central app (operator)" ticked when shown. No password, token or cookie is printed.
Site-side checks: `studio wp eval` on CM_MCP_OAuth (grants named "Monks Central", refresh-token rows).

Keep test data (plan section 11): the four Studio sites are connected in the app's default data folder
(~/.local/share/com.classicmonks.monks-central) and stay connected. Tests that break a connection on
purpose (corrupt secret, remove) used an extra connection in a throwaway data folder, cleaned up after.
The preview app (/home/joy/dev/monks-central-preview) was closed before the run.
