Monks Central, Phase 3 "Content": live acceptance on WordPress Studio sites
Run: 2026-10-28, Linux (Hyprland), main. Driver: crates/core/examples/acceptance.rs (types, get,
create, edit, import), which calls the same core API as the app, plus the real app window
(target/release/monks-central) for the screenshots. Data folder: the app's default
(~/.local/share/com.classicmonks.monks-central); no test broke a connection on purpose, so no extra
connection was needed. No password, token or cookie is printed. Site-side checks use `studio wp`.
Classic Monks Pro feat/monks-central (M6) was copied onto mc-a and monks-central-test (rsync, no
deletes). mc-b stays on 2.5.0 on purpose; mc-c is Basic mode (core REST, application password).

Fixtures made with `studio wp` before the run (kept on the sites):
  mc-a                AI Custom Fields turned on; post type mc_recipe "Recipes" and taxonomy
                      mc_course "Courses" made with Classic Monks' own builder (save-post-type-def);
                      term Breakfast (16); page 12 "Phase 3 block page" (heading with a class,
                      drop-cap paragraph, columns > column > separator / paragraph / list > 2 items,
                      buttons > button, latest-posts void block); page 13 "Phase 3 Elementor page"
                      (_elementor_edit_mode builder, _elementor_data with a container and a heading)
  monks-central-test  page 14 "Phase 3 Bricks page" (_bricks_editor_mode bricks, _bricks_page_content_2)
  mc-c                page 15 "Phase 3 Elementor page (Basic mode)", same Elementor meta as page 13
